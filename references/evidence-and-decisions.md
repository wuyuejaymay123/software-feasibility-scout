# 证据与判断

## 证据单位与可靠性

一条证据是能定位到具体来源、作者和时间的经历或事实。记录稳定链接（尽量到具体评论）、平台、原始日期、事件日期（若明确）、核查日期、来源类型和简明转述。必要时保留短原文与中文译文，明确区分原文和转述；不批量保存整帖或个人资料。

支持需求的强材料包含：具体任务、触发场景、实际障碍、发生频率、当前做法、已投入的成本或已尝试的解决办法。亲身经历也可能错误或有偏差，应标成用户自述，而不是外部核实事实。

独立性按不同作者的不同原始经历核验；同一人的跨平台发布、转载、同一评论编辑、同一事件复述只计一次。不同账号不保证不同真人，无法确认时保留疑点。点赞、关注、跟帖附和和搜索结果数作为辅助信息，不计入独立需求人数。

将推广、联盟链接、竞品攻击、纯假设、泛泛情绪、无法追溯的聚合文排除出核心证据；依据内容和上下文说明疑点，不只凭文风判断机器人。AI 生成的评论摘要不替代原始评论。搜索摘要与不可打开的原文仅为待核查线索。

## 当前有效性

先判断问题属于哪种机制，再决定观察窗口，记录理由：

| 机制 | 当前性核验 |
|---|---|
| 快变功能、版本故障或事件 | 最新官方版本/变更与变更后用户经历；事件结束后是否仍存在需求。 |
| 长期重复工作流 | 多个时期的独立经历、现行流程与替代成本，区分持续障碍与一次故障。 |
| 季节性或低频高价值任务 | 最近相关业务周期与当前条件；比较相同周期，不要求每周有讨论。 |
| 新出现的任务 | 触发变化是否持续、是否出现独立使用场景；短期热度与真实任务分开。 |
| 短期事件或阶段性产品 | 核事件时点、搜索/内容信号的当前活跃度、开发和触达所需时间、可收费交付物、窗口结束后的停止或复发条件；短期本身不构成淘汰理由。 |

30/90 天只能作为便利的初始检索窗口，不作为有效期。旧内容可说明长期背景；要推荐现在开发，需当前条件或近期相关周期的证据。刚被索引、编辑或顶帖不自动刷新需求年龄，新评论必须提供实质新信息。

最近没有搜到表示当前证据不足，不等于需求不存在。只有比较范围、语言、查询、采集方式和时间长度足够一致时，才描述样本中的变化。使用“本轮发现的独立经历”，而非推断全站讨论增长率或市场规模。

保存“最后实质证据时间”和“最后核查时间”两个字段。复查间隔由变化速度、下个业务周期、发布更新或其他触发点决定；每次写明下一次核查日期/条件及理由。

## 多来源核验

每个准备进入行动推荐的候选，主动完成以下三类查证并记录结果：用户经历、现有解法、经济/购买线索。至少尝试一类相关的非 Reddit 用户来源，以及官方解法或人工替代来源；失败或无结果按缺口报告。Google/TikTok 热点可以先触发候选，但须证明热词或视频背后有可执行的用户任务。三平台证据可相互印证，也可冲突；不要求三平台都出现才允许推荐，缺失的重要一路需说明。对已出现决定性反证而归档的候选可提前停止，注明原因。未入选的弱线索不必执行完整深挖。

| 缺口 | 可选来源 | 能证明什么及边界 |
|---|---|---|
| 独立经历或实时性 | Reddit 其他讨论、行业论坛、公开支持社区、应用商店评论、GitHub Issues | 具体人的问题和后续；同一事件跨平台不增加独立性。 |
| 是否已解决 | 官方功能文档、更新日志、作者后续、开发者回复、现行替代流程 | 对应版本与适用人群是否解决；关闭 Issue 不必然代表完成。 |
| 支付/投入 | 用户现有支出自述、付费替代、公开采购/外包需求 | 已有成本或预算线索；报价、标价、询价不是成交，支出自述须标来源。 |
| 搜索和触达 | 任务相关搜索结果、具体社区及其规则、应用类别、当地语言论坛 | 潜在入口；不是转化率、获客成本或可自由推广的证明。 |
| 搜索/内容热点及窗口 | Google Trends Trending Now/Explore、TikTok Creative Center 的具体趋势项和原始视频、跨周期公开资料 | 可发现突发与阶段性任务；热度指标不等于用户数、利润或付费。 |

选择与方向相关的来源：软件工作流可查产品官方社区、GitHub Issues 或应用/插件商店评论；职业任务可查行业论坛；购买线索可查公开采购、外包需求和用户现有开销。读取具体条目与后续，平台名称或聚合星级不能替代经历。推广案例、带激励评论或厂商客户故事需注明来源关系，不单独充当独立需求证明。

日常发现按 [热点信号与机会窗口](trend-discovery.md) 主动尝试 Google Trends 与 TikTok；深挖时按候选关键缺口继续查。记录词/话题、地区、观察窗口、原始发布时间与指标性质。Google 网页搜索不等于已查询 Google Trends；趋势指数不是绝对搜索量，TikTok 播放量也不是独立买家数。没有可访问数据时写未知，不编造搜索量。

多来源查证不要求凑固定平台数。同一平台可以提供多个独立经历，官网可以提供当前功能反证，但厂商报价不能顶替独立用户佐证。只有 Reddit 用户经历时，明确“尚无站外独立经历”；若当前性、真实性或购买价值的关键缺口因此未解决，保持 experiment/watch，不包装成跨平台需求已验证。站外搜不到不直接等于没有需求，也不单独否定已有可靠经历。

在机会文件中列出“用户经历／现有解法／经济或购买线索／趋势及窗口”四行核验表；指定单一需求深挖时可注明趋势未查。各行给原始来源、核实状态与证据边界。合并前按作者、原始事件与引用关系去重：同一经历的博客转载、跨平台发布、翻译和不同搜索引擎命中只计一次。跨语言合并需核对工作流、付款方式、地区条件；不同人群或版本的冲突分别保留，不取多数意见掩盖反证。

无竞品时查人工、表格、外包或多工具拼接，并记录已搜索的词、语言与范围。结论写“本次未找到直接竞品”，继续评估现行替代，而非推断无竞争。

## 反证与产品成立条件

每个行动推荐至少记录一次实质反证搜索及结果：已修复/已满意、现有免费方案够用、配置或知识问题、迁移阻力、一次性事件、强烈价格敏感、抱怨者没有购买决策权。没有搜到反证不等于证明不存在。

明确用户想完成的任务，而非照抄用户提出的功能。检查该问题能否形成独立付费价值，或只适合某平台插件/现有工作流里的一个步骤。游戏等体验产品可用游玩、重复使用与实际购买检验，不能把喜欢某个点子当成购买验证。

分别说明：使用者、付款者、当前替代、切换触发因素、迁移/学习负担、一个可触达入口。热点驱动的候选还须说明为何用户需要独立工具，而非浏览同一条视频/搜索结果即可解决；何时交付才赶得上窗口。公共社区存在仅说明用户可能聚集，实际推广方式须检查规则；具体执行留到选定产品后。

## 经济与交付可行性

从当前指令、有效对话与个人配置读取用户预算及费用口径；未设时使用 SKILL.md 的参考档位做对照，并明确“用户预算未确认”。用户明确暂缓预算规划时，本轮只标记“预算待定/延期”，不估费用或用参考金额筛选；真正提出投入决定前再补。参考档位不是上限，成本超过参考值的机会仍可保留并解释成本结构，不能仅据此归档。用户给出明确上限时按该上限筛选，超限先评估缩减范围并标明缺口；不能自行调高用户上限。用户使用其他币种时保留原值与币种，需要比较时注明汇率查证来源。

列出验证至上线首月累计现金支出：一次性/年付的实际首笔支付、托管与数据库、AI/API、域名及邮件、必要数据/账号费用、测试推广和合理余量。已有共享服务按增量现金支出计算，并披露假设。显示原币报价、查证日期与人民币换算依据；尚未核实则给出假设区间，不写成确定报价。

估算低用量与较高用量情景；AI 产品至少说明一次核心任务的输入/输出或调用次数、单位费用及付费重度用户的成本。收入定价是待测试假设；毛利估算注明支付渠道费用、退款等纳入范围，不推算虚构成交量。

将两周开发范围与外部审核、平台接口、授权、数据来源、硬件和必要专业能力分开核查。只检查与该候选实际相关的依赖。核心前提无法确认时保留实验/观察结论，不以“AI 可以做”替代可行性判断。

- [Apple 评论说明](https://developer.apple.com/help/app-store-connect/monitor-ratings-and-reviews/ratings-and-reviews-overview/)：地区、评论更新与公开摘要；优先读具体评论。
- [GitHub Issue 检索](https://docs.github.com/en/search-github/searching-on-github/searching-issues-and-pull-requests)：创建、更新、关闭及关闭原因要分别解释。
