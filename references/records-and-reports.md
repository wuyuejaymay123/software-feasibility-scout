# 记录与报告

## 可移植的数据目录

沿用用户明确指定的数据目录；否则用当前工作目录的 `demand-research/`。首次创建时在报告中显示完整实际路径。用户切换 Agent 时指向相同目录即可继续；不同电脑/云端需用户自行提供或同步该目录，安装技能不会自动同步数据。

使用 UTF-8 Markdown 和 JSON，无数据库、Python 或专用存储依赖。目录只按使用需要创建：

```text
demand-research/
  profile.json
  index.json
  opportunities/OP-0001.md
  reports/2026-09-22-091500.md
  runs/2026-09-22-091500.json
```

文件名日期只是格式示例，每次使用实际本地日期与时间；同秒重跑加后缀，保留旧报告。

`profile.json` 只记录用户相对于技能默认值的覆盖配置，可从 `{}` 开始。可选字段：`report_language`、`timezone`、`cash_budget_cny`、`mvp_weeks`、`review_weeks`、`included_markets`、`excluded_categories`、`sampling_plan`（standard/quick/focused）。采样计划定义见 [搜索覆盖与采样](search-and-sampling.md)。当前指令高于该配置；临时要求不自动写成长期偏好。

方向设置使用 `direction_mode`（user/auto）和 `research_direction`（用户指定的自然语言边界）；auto 模式下具体选题保存在本轮 scope。人民币明确上限沿用 `cash_budget_cny`（数值，0 也是有效上限）；用户明确暂不设预算时设为 null，缺字段表示尚未设置，不能与零混淆。其他币种或复杂费用口径使用 `cash_budget` 对象保存用户的 amount/currency/period/note，并替换旧预算字段以免冲突；未明确的值留 null。迁移旧配置时保留用户已设数值，不能把它误当参考金额自动清除。

首次索引：

```json
{
  "schema_version": 1,
  "next_id": 1,
  "last_attempt_at": null,
  "last_completed_at": null,
  "last_successful_at": null,
  "coverage_rotation": [],
  "coverage_checkpoints": [],
  "opportunities": []
}
```

新增机会分配 `OP-0001` 这样的永久 ID，再递增 `next_id`。索引的每条 opportunity 包含：`id`、`title`、`segment_task_key`、`verdict`、`stage`、`first_seen_at`、`last_substantive_evidence_at`、`last_checked_at`、`next_review_at`（未知可为 null）、`review_trigger`、`last_reported_at`、`file`。日期可用 ISO 8601；只有年月等粗粒度日期时在机会正文保留原始精度，不编造具体日/时间。

`verdict` 为 `build/experiment/watch/archived`；`stage` 为 `unstarted/building/live/paused`。研究推荐不会把 stage 自动变成 building。只有用户提供或可访问的真实项目事实才能推进阶段。

机会正文包括稳定分组键、市场边界、证据表、去重说明、时效机制、付费/替代/迁移分析、反证、决定理由、下一动作/复查触发及历次状态变化；费用估算遵从用户本轮要求，明确延期时标“预算待定”。热点驱动候选另记录 `opportunity_horizon`（evergreen/seasonal/event_driven/flash）、触发事件、趋势原始时点、地区/窗口、预计可销售期及其依据、交付时滞和过期条件。证据表至少列：证据 ID、链接/平台条目 ID、作者可见标识（仅去重所需）、原始日期、事件日期（可未知）、核查日期、类型、简明内容、支持/反证、核实程度。不推断作者真实身份。

## 去重与更新

先用平台条目 ID/规范链接去重，再按作者及经历、目标人群与任务识别语义重复。删除纯跟踪参数时保留真正定位评论所需信息。同文转载和翻译合并到原证据；同一原帖的不同评论可以是不同经历，但须核查而非按评论数计数。

同一用户补充新情况可更新证据，但不能增加独立用户数。新增相关独立经历、解决状态变化、可核验的新支付或替代信息才构成实质更新；本轮重新打开页面只改变核查时间。

每轮创建 run 记录：`run_id`、`started_at`、`finished_at`、`status`、`mode`、`evidence_mode`、`reference_time`、`scope`、`queries`、`sources_opened`、`access_gaps`、`changed_ids`、`report_file`。`status` 取 `complete/partial/blocked`；scope 含实际社区/站点、语言、时间范围、窗口理由和本轮探索场景。

新运行另按 [搜索覆盖与采样](search-and-sampling.md) 保存访问方式、采样计划、筛选表、实际数量与停止原因。旧运行缺少这些字段仍可读取，不能把缺失解释为零。筛选表遵守与证据相同的来源删除和最小留存要求。

每轮另存 `direction`（本轮边界、user/auto、来源和选择理由）与 `budget`（用户上限或未设、币种、费用口径、是否仅参考）。报告明确这两项。历史记录按原时点约束保留，不因配置变化重写旧结论；复查候选时用当前约束重新判断并记录变化。

scope 增加 `source_coverage`，分别记录 Reddit、Google Trends/搜索、TikTok、其他用户来源、官方/竞品的目标站点、实际访问服务、已读结果与缺口；未知提供方写未知。Google 热词需存查询/趋势项链接、地区、时间窗、记录时刻及指标性质；TikTok 需存可见话题/视频链接、地区、窗口、实际读到的描述/评论与访问状态。机会正文按 [多来源核验](evidence-and-decisions.md) 保存核验表。旧记录不补造站外核查与搜索服务历史。

`evidence_mode` 为 `live/supplied/simulation`，分别表示实时查证、仅分析提供材料、合成回放；混合运行在证据条目中分别标注。运行时间使用实际时钟；材料或回放设定的截止时间放入 `reference_time`，报告同时显示两者。合成回放仅写独立验证目录，不能进入真实机会库。离线分析按其请求范围完成可标 complete，但不能推进实时覆盖检查点或实时 `last_successful_at`。用户材料中声称已查证的内容标为提供者陈述；模拟推荐仅在合成前提下成立，不变成真实开发建议。

先保存机会详情和报告，最后更新索引。更新前重新读取索引，发现其他运行已修改则合并或明确报告冲突，避免覆盖他人的新记录。支持安全临时文件替换时采用该方式。保持单个数据目录同一时间只有一个写入者。

`last_attempt_at` 记录尝试；有可交付报告与一致状态时更新 `last_completed_at`；只有计划范围的调研实际完成时更新 `last_successful_at`。这些全局时间仅用于运行概览，不作为所有来源的统一增量起点。

`coverage_checkpoints` 按来源/社区、语言和任务场景分别记录 `scope_key`、`checked_through`、`run_id`。只有该范围的计划查询实际完成才推进相应检查点；受阻范围保留旧值。下一轮按对应范围补查并留适当重叠，依靠去重处理重复。一次指定需求深挖、某个新社区成功或部分访问成功，不能推进未检查范围的时间。旧索引没有此字段时从 runs 的明确覆盖记录恢复；无法确定就回溯搜索，不能假定已覆盖。

若目录不可写，在对话中交付报告和待保存变化，明确“本次未持久保存”，不声称以后自动记得。索引损坏或版本不识别时保留原文件，读取可用机会详情；无法可靠更新就报告未保存，不重置历史。

源内容删除、撤回或不可用时记录可核实的状态；不能把访问失败认定为删除。遵守来源适用的数据保留要求，必要时清除留存摘录并重新评估依赖它的结论，不另寻被删内容的副本。

## 日报模板

以结论开头，摘要控制在用户能快速决定下一步的长度；详细证据放在机会文件。下列项目是语义要求，可调整排版。

```markdown
# 需求机会日报 · 实际日期

调研截止：实际时间及时区
本轮状态：完成 / 部分完成 / 受阻
本轮方向：用户指定 / 自动选择，具体边界与理由
预算依据：用户金额、币种与口径 / 尚未设定、仅参考估算 / 用户要求延期，本轮不规划
覆盖：本轮实际市场、人群、语言、来源与时间范围
采样：计划与实际查询、去重初筛、原帖、评论、外部页面、受阻条目数量；未知项标明
访问方式：搜索服务/公开网页、已授权浏览器、获准 API 或离线材料
来源覆盖：Reddit、Google 热词/搜索、TikTok 热点、其他站外用户经历、官方解法、购买/支出线索；逐路说明实际访问、原始信号、冲突与缺口
访问或取样缺口：具体缺口；无则写无

今天最值得采取的行动：具体建议，或没有达到标准的推荐。

## 行动推荐（总计 0–3 个）

### OP-编号 · 机会名称 · 优先开发小版本 / 快速实验

- 用户、付款者与任务：具体人群、场景和目标。
- 原始证据：核心链接、日期、短原文/转述；独立经历数及去重依据。
- 交叉核验：站外经历、现有解法与经济线索的实际结果；支持、反证、未知分别说明。
- 为什么现在成立：最新实质证据、环境/版本/周期核查。
- 机会窗口：长期/季节/事件/短期；起止或未知、交付与触达时滞、过期条件。
- 付费依据：事实、自述与假设分别标注。
- 现有替代及切换理由：包含免费/人工替代与迁移成本。
- 反证与最大未知：实际检查结果，什么会推翻推荐。
- 第一版范围：必要能力、暂缓内容、预计时间与外部依赖。
- 现金预算与用量：累计首月估算、单位成本、关键前提；用户本轮要求延期时只写“预算待定，未规划”。
- 首批用户入口：具体链接或可执行的触达路径假设。
- 下一步：一个可执行动作及可观察的判定条件。
- 与上次相比：首次发现，或具体新增/变化；详细记录链接。

## 观察线索与状态变化

只列有信息价值的线索、降级/归档或重新打开的机会；写明原因与复查触发。

## 本轮记录

调研实际路径、索引和运行记录位置；是否成功保存。
```

没有合格推荐时保留截止时间、实际覆盖、阻碍和下一轮查证重点即可。技术故障不能包装成市场无需求。任何数值没有可靠证据时写未知或明确的估算区间，不补齐虚构样本、日期、收入和用户。
