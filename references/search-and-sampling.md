# 搜索覆盖与采样

## 先确定用户方向与预算

范围优先级：本次明确指令 > 对话中仍有效的约定 > 已保存个人配置 > Agent 自选。首次缺少方向时先问一个问题，例如“你想优先找哪个行业、人群或任务的需求？没有方向也可以由我来选。”用户已明确委托选择时直接执行。方向可以较宽，也可以很具体，无需用户先给出产品点子；“AI 工具”属于产品形态，仍要在该形态内选择具体人群与任务。

方向明确后只询问尚不清楚的预算，例如“单个产品从验证到上线首月，你希望投入多少现金？可以给上限或先不设；技能有一个参考档位供估算。”参考金额与口径以 SKILL.md 为准。一次一个问题；预算暂不确定不阻止公开资料研究。用户明确要求暂不做预算时记录延期并继续其他研究；真正准备投入决定前再补。用户要求直接开始、未提供设置或定时任务无法互动时，记录假设并按默认规则继续，不把未回答当成确认预算。已有方向/预算时直接沿用，用户随时可以修改。

有用户方向时，将其转成可执行边界：包括的人群/任务、明确排除项、地区或语言（若有）。例如“摄影行业”可探索选片、预约、交付、客户沟通；不因其中一个任务冷清就转去记账行业。用户明确允许探索相邻方向时才扩大边界。范围太窄时调整关键词、社区、时期与子任务；仍不足则报告证据缺口并建议扩大方向，不悄悄改变用户范围。

没有方向或用户委托选择时，结合已知技能、时间、预算、可触达用户、近期历史覆盖与重复任务，选择适合该采样计划的探索组。未知能力只用参考假设，不捏造用户资源。先说明选择理由，再找证据；选择方向不等于断言那里有商机。自动选择记录在本轮，不固化为用户长期兴趣；后续可以依据证据轮换，用户一旦指定方向立即优先。

首次明确设定的长期方向与预算写入 profile；“今天只看……”仅写本轮。用户说“以后自动选”可保存自动模式；说“预算暂不定”保存未设状态，后续不每天追问。机会成本变化或准备作投入决定时，再提示需要确定的成本条件。新的用户预算覆盖参考档位，但不会改写历史报告中的旧约束。

## 先确认来源能力

本技能是研究流程，不内置 Reddit 数据库、采集器、搜索额度或调度器。使用 Agent 实际提供的合适工具，先试一次搜索和原文读取，记录本轮访问方式及成功/失败。支持安装技能不等于来源访问效果相同。

| 可用方式 | 运行范围与限制 |
|---|---|
| 搜索服务与公开网页读取 | 使用者无需先提供自己的 Reddit 账号也可开始；能读到哪些原文取决于提供方、地区与页面限制。搜索结果不是完整 Reddit，索引时间不是发表时间；普通网页搜索不等于已直接查 Google Trends 或 TikTok。 |
| 已授权的浏览器会话 | 仅使用用户已授权且平台允许的访问；不自动创建账号。登录不保证全评论、私有社区或搜索全集可见。 |
| 已获准的 API/数据服务 | 检查实际授权、用途和额度后使用；普通账号不等于 API 批准，不能假定公开 JSON 地址是无需授权的接口。 |
| 只有用户材料或离线能力 | 做 supplied 模式分析，记录材料截止时间；不能报成当天联网发现。 |

若部分原文受阻，继续可访问范围并报缺口；核心原文都打不开时，结果为线索而非已核验推荐。账号、API 权限、网页可读性是三个不同条件。扩大到批量采集、商业数据服务或更换访问渠道前核对其用途许可；技能安装本身不提供这些授权。

## 搜索维度与表达

先选角色和任务，再生成不同类型的查询，避免只搜创业点子或“我愿意付钱”。每个方向至少使用任务描述和障碍/替代两种表达；具体词随行业与语言变化，不机械穷举笛卡尔积。

| 维度 | 要找的内容 | 示例表达（按具体任务替换） |
|---|---|---|
| 角色、工作阶段 | 谁做、替谁做、谁付款，月结/交付/入职等触发 | bookkeeper、photographer、onboarding |
| 重复操作与变通办法 | 来回复制、表格维护、拼接工具、找人代做 | manually、spreadsheet、copy paste、every month |
| 障碍与损失 | 时间浪费、遗漏、返工、客户流失；不要求用户骂产品 | takes hours、missing、keeps failing |
| 寻找与替换方案 | 求工具、迁移、太贵、不适用、还缺什么 | how do you、alternative、switching from |
| 经济与购买动作 | 已付费、雇人、预算、采购决定和切换成本 | paying for、hired someone、budget |
| 反证和后续 | 已解决、原生功能、满意用户、降价或版本更新 | solved、built in、works for me、release notes |

每条候选回到原文，提取：用户/付款者、任务、频率、严重程度、现行做法与实际成本、未满足之处、发生时间与后续。无法确认就保留未知；不从一串抱怨补出用户没有说过的损失金额。

## 三路发现与多来源核验

日常发现按 [热点信号与机会窗口](trend-discovery.md) 尝试 Reddit、Google Trends 热词和 TikTok Creative Center 三个并行入口。先轻量扫描各入口，不以 Reddit 关键词预先限制 Google/TikTok 的候选。用户指定单一需求深挖时，按尚缺的证据选入口，无需凑三平台。可用 Google 时直接使用；只能用 Agent 的网页搜索时照常执行，记录真实工具/提供方，提供方未知则标未知，不声称搜索过 Google。TikTok 登录或地区限制按实际记录。用户明确只允许某来源时尊重限制并说明缺口。

站外查询从任务、人工替代、工具问题与解决状态展开，例如“任务 + workflow/manual”、“工具 + missing feature/alternative”、“任务 + forum/review”。必要时用排除 Reddit 域名的查询寻找站外原文，但只有工具实际支持该语法才采用。复用用户真实措辞并增加同义表达；不同语言按目标市场扩展。

热词、话题和搜索服务都是发现渠道；最终任务证据来自读到的具体原始页面、视频或评论。Google 与其他搜索服务返回同一 Reddit 帖子仍只算一份经历；SEO 榜单、转载和搜索摘要仅作导航。Google 查询、TikTok 视频和 Reddit 评论用不同计量单位记录，不合算为“需求总量”。

准备行动推荐前，按 [多来源核验规则](evidence-and-decisions.md) 分别检查独立经历、现有替代和商业线索，主动找相反结论。来源根据目标人群选，不要求每天机械访问所有平台，也不依靠增加链接数来升级结论。

## 工作量目标

以下是针对个人开发者日常研究的初始工作量设计，尚非经过效果校准的统计抽样标准。先记录目标，再报实际；不保证每天都有这些数量的相关可读材料。

| 计划 | 角色/工作流与社区 | 查询与初筛 | 原文核查 |
|---|---|---|---|
| standard：默认日常发现 | 3–5 个角色/工作流组，合计约 6–10 个相关社区；并行尝试 Google/TikTok 热点入口 | 网页/Reddit 约 12–24 个定向查询；另记录实际查看的 Google 趋势项与 TikTok 话题/视频，不把其浏览数混进查询数；目标初筛 40–80 个去重的候选内容项 | 约 12–20 个相关 Reddit/垂直社区原帖；热点触发时读关键搜索页面、视频及评论；深挖最强的 1–3 个候选 |
| quick：用户要求试跑或快速查一下 | 2–3 个组，约 3–5 个社区；可达时扫三路入口 | 约 6–12 个查询，另记实际热点项；目标初筛 15–30 个内容项 | 约 5–8 个原帖/具体视频；结论仅限本次小范围 |
| focused：指定需求深挖 | 围绕同一人群与任务 | 围绕缺口查独立经历、时间、替代、支付与触达；不扩无关行业 | 以关键决策缺口是否消除停止，不凑帖数 |

不同社区可以属于同一角色，不能将两个记账任务加一个摄影任务说成覆盖三个行业。社区、查询、热词、话题、视频、评论、独立经历是不同计量单位。官网不计入 Reddit 原帖数；一页几十条评论不代表几十个已审查需求。热点入口增加发现路线，不能为凑数量无限扩搜；提前停止低增益扫描并报实际覆盖。

查询目标包含 Reddit 与站外查询总数，站外核验从同一工作量预算中安排。论坛帖子、评论与官网分别记录来源和类型；汇报时拆开 Reddit 原帖、站外用户材料和官方页面，不把全部原文核查数写成 Reddit 帖数。

角色/工作流组均从用户方向内拆分；方向很具体时可少于表中组数与社区数，记录理由并加深该任务核验。单个行业方向仍可执行 standard 发现，不自动变成只验证一个点子的 focused 模式。

以上上界用于限制工作量。遇到强线索可以提前停止该候选，其他已计划方向仍需检查；若来源不足、连续两轮低增益、时间/工具额度有限，可提前结束并说明偏差及其对结论的影响。更多重复数据不会补足支付证据。用户指定时间或费用上限时优先遵守，不擅自购买数据。

## 降低覆盖偏差

日常发现保留两条 Reddit 路线：有关键词的任务搜索，以及允许访问时的所选社区近期帖子浏览；同时通过 Google/TikTok 的宽热点扫描发现尚未写成“需要软件”的事件。只能用搜索服务时，将社区浏览替换为宽查询，明确它仍有索引盲区。

可用时组合 New 与 Relevance，历史 Top 仅补背景；实际没有调用 Reddit 原生排序就写“搜索服务排序”。至少查看一个低互动但任务具体的近期条目；没有找到则记录。原帖评论核查覆盖作者后续、使用现有方案的人和相反观点，不只看最热评论。记录只看了部分评论及不可展开的范围。

发现阶段可先看近 7–30 天，再扩至近 90 天或最近相关业务周期；这只是检索次序，有效性仍由任务机制决定。原始日期、事件日期、页面抓取日期、此次核查日期分别处理，后两者不能刷新需求年龄。

读取最近 7 次运行的覆盖记录，在有效方向边界内选近期未查或长期未查的子任务/人群，并兼顾范围内到期候选；首次运行在边界内选择有差异的组。仅在自动选方向或用户已允许跨方向时扩大角色池。具体单任务无法轮换时改查不同表达、社区或时间段，不制造范围外任务。某个组连续两次只有重复或广告时降低频率，保留重开条件，不判定整个行业无需求。范围外旧候选可保留待复查状态，本轮不自动深挖，也不因未查而归档。

英语是可选起点，不是永久市场限制。有明确地区线索时增加当地语言查询，核对该地区工具、支付与工作流；没有做当地检索时不宣称已验证那个市场。每 7 次运行汇总角色、社区、语言及遗漏范围，这是覆盖盘点，不是全市场覆盖率。

Reddit 和其他公开社区的发言者都是自选样本。用户量、市场规模、真实支付比例或讨论增长率不能从搜索命中数外推；比较时间变化需要相同查询、窗口与采样方法。多来源核验优先补关键缺口；平台之间结论冲突时核对人群、版本、日期与业务环境，保留分歧，不按赞成票多数决定。

## 保留可核对的筛选数量

运行过程中增量写轻量筛选表，默认在 `runs/<run_id>.screening.jsonl`，与运行记录关联。每行只需：平台条目 ID/规范链接、来源/社区、类型（post/comment/video/review/issue/vendor/procurement/trend）、query_ids 或 trend_id、读取状态、结论标签和简短排除理由。趋势项另记地区、窗口、观察时间、原始发布时间（可未知），避免把今日看到的旧视频当新需求。无需复制全文或收集作者画像。重遇同一条目更新关联 id，不重复计数。

标签可用 irrelevant、promotion、duplicate、resolved、lead、evidence；读取状态可用 snippet_only、original_read、blocked、removed。进入机会证据表的评论再保存足以定位和去重的信息。评论只有实际读过且有记录才计入评论核查数；线程可读不等于所有评论可读。

运行记录新增 `sampling_plan`、`access_mode`、`screening_file`、`metrics`、`stop_reason`。metrics 至少区分：查询数、初筛去重条目数、可读原帖数、已核查评论数、外部页面数、受阻条目数、候选数和行动推荐数；热点运行另计 Google 趋势项、TikTok 话题/视频与实际可读评论，未访问写 `null` 而不是 0。按记录计算；无法追溯则 null 并说明，不用搜索结果显示的总命中量代替。各项可能重叠，不机械相加。

queries 新条目记录 query_id、文本、实际搜索服务、目标来源与目的；旧条目只有查询文本也可读取。metrics 增加按平台/来源类型的分项数量，独立经历数在机会中按同一原始经历去重，不按搜索服务数统计。来源覆盖表分别写“计划检查、实际读到、能支持什么、仍缺什么”。

每轮摘要同时给出计划/实际/差距，例如“计划读 12–20 帖，实际 9 帖；其余受阻，当前性结论受限”。旧记录不补造初筛数量或读取时间，新字段可缺省；有明确证据才追加注明为回顾统计。

## 判断是否足以做下一步

区分流程覆盖与商业证据：完成采样计划只能说明检查了计划范围；多个独立经历可以支持尝试，实际付款和持续使用需要真实行为验证。存在竞品只是市场与替代信息，只有对当前目标人群足够好且无明确切换理由才构成归档反证。

实验单列“本地可准备的演示/对照”和“需要真实用户参与的验证”，后者没有参与者就写待执行；模拟数据、内部评审和 Agent 扮演用户均不能满足付费或需求验证门槛。区分表面根因（缺一个页面）与实际根因（客户不配合、流程不执行、权限或法规限制）。

每 7 次运行盘点重复率、可核查来源比例、各方向有效经历与反证、用户接受/拒绝推荐的原因。只有有真实后续时才统计实验、开发、付费转化；不把模型认可自己的推荐当效果验证。搜索/API/模型成本与产品现金预算分开报告；查不到实际计费则写未知，不能把没有采购服务等同于运行免费。
